# ПОС — Преподавательская Оценка Студентов

Консольное приложение для учёта студентов, критериев оценивания и выставленных оценок. Приложение рассчитывает итоговый балл студента по весам критериев и экспортирует результаты в CSV.

## Возможности

- добавление студентов и критериев оценивания;
- просмотр списков студентов и критериев;
- выставление и изменение оценки по критерию;
- просмотр и удаление оценок студента;
- расчёт итогового балла по выбранной стратегии;
- экспорт результатов в CSV.

Оценка должна находиться в диапазоне [0, maxScore]. Выставить её можно только существующему студенту и по существующему критерию.

## Запуск

Требуется Go версии 1.27.4 (указана в go.mod).

Из корня проекта:

```bash
go run ./cmd/pos
```

## Архитектура

Использована облегчённая Ports and Adapters (Hexagonal Architecture). Домен не зависит от консоли, файлов и инфраструктурных реализаций. Сборка зависимостей выполняется на внешнем краю приложения — в internal/container.

```text
cmd/pos/                 точка входа
internal/
  domain/                доменная модель, инварианты, порты и Domain Service
  application/           сценарии приложения и интерфейс экспортёра
  infrastructure/        реализации репозиториев в памяти и CSV-экспортёр
  cli/                   консольный интерфейс
  container/             сборка зависимостей (Composition Root)
```

Направление зависимостей:

```text
CLI ──> Application ──> Domain
          ^                ^
          |                |
Infrastructure ────────────┘

Container создаёт реализации и связывает компоненты.
```

Application использует доменные интерфейсы репозиториев. Infrastructure реализует эти интерфейсы. Интерфейс Exporter объявлен в Application, а CSV-реализация находится в Infrastructure.

## DDD: доменная модель

В коде используется единый предметный язык: Student, Criterion, Evaluation, итоговая оценка.

- `Student — Entity`: имеет устойчивый идентификатор ID; создание через NewStudent проверяет и очищает ID и имя.
- `Criterion — Entity`: имеет идентификатор, название, максимальный балл и вес. NewCriterion проверяет непустые ID и название, положительный максимум и конечный вес в диапазоне [0, 1].
- `Evaluation — Value Object`: описывает факт выставления конкретного балла студенту по критерию. У него нет собственного идентификатора; равнозначность определяется значениями studentID, criterionID и score. В хранилище запись адресуется составным ключом (studentID, criterionID), чтобы оценку по тому же критерию можно было обновить.
- `EvaluationFactory` создаёт Evaluation и проверяет наличие ID студента, корректность критерия и диапазон/конечность оценки.
- `Repository` — доменные порты StudentRepository, CriterionRepository, EvaluationRepository; реализации хранения находятся в Infrastructure.
- `ScoreCalculator` — Domain Service: получает оценки и рубрикатор, проверяет входные данные и рассчитывает итог. Итог не может быть меньше 0 или больше 10.

Границы агрегатов и выбор Evaluation как Value Object — осознанное упрощение модели для текущего объёма задания. В дальнейшем при появлении самостоятельной истории оценок, дат, комментариев или апелляций модель можно пересмотреть.

## GoF

В проекте применены по одному паттерну из каждой группы:

| Группа | Паттерн | Где и зачем |
|---|---|---|
| Порождающий | Factory | EvaluationFactory — единая точка создания Evaluation с проверкой доменных правил. |
| Структурный | Facade | POSFacade — предоставляет CLI единый интерфейс к сценариям нескольких Application Services. |
| Поведенческий | Strategy | CalculationStrategy и две реализации — позволяют менять алгоритм расчёта без изменения ScoreCalculator и использующих его сервисов. |

По умолчанию контейнер выбирает WeightedSumStrategy. Также реализована NormalizedWeightedStrategy.

Используемые формулы. Пусть `pᵢ = scoreᵢ / maxScoreᵢ`, `wᵢ` — вес критерия:

- WeightedSumStrategy: `min(10 × Σ(pᵢ × wᵢ), 10)`.
- NormalizedWeightedStrategy: `10 × Σ(pᵢ × wᵢ) / Σwᵢ`; если сумма весов равна нулю, результат равен нулю.

Первая стратегия не перераспределяет вес критериев, по которым нет оценки. Вторая нормирует результат по сумме весов критериев, для которых переданы оценки.

## DI и Composition Root

internal/container/container.go вручную собирает граф зависимостей: создаёт репозитории, EvaluationFactory, ScoreCalculator с выбранной стратегией, CSV-экспортёр, Application Services и POSFacade.

cmd/pos/main.go только создаёт контейнер, CLI и запускает приложение. Сторонняя DI-библиотека не используется.

## Тестирование и проверки

Запуск тестов:

```bash
go test ./...
```

Тесты Domain проверяют инварианты Student и Criterion, создание Evaluation, расчёт итоговой оценки, граничные и некорректные входные данные, а также обе стратегии. Тесты Application проверяют выставление, обновление, получение и удаление оценок, проверки существования студента и критерия, а также отклонение `NaN` и `Inf`.

## Тестовый сценарий

Для сквозной проверки программы можно выполнить команду из корневой папки проекта. Сценарий добавляет студента и два критерия, выставляет оценки, рассчитывает итог и сохраняет результаты в файл results.csv.

```bash
go run ./cmd/pos <<'EOF'
1
001
Ivan
2
hw
Homework
10
0.5
2
exam
Exam
10
0.5
5
001
hw
8
5
001
exam
10
7
001
9
results.csv
0
EOF
```

Ожидаемый результат:

- Добавлен студент с ID 001 и именем Ivan.
- Добавлены критерии Homework и Exam с максимальным баллом 10 и весом 0.5 каждый.
- По Homework выставлено 8 баллов, по Exam — 10 баллов.
- Итоговая оценка студента — 9.00 из 10.
- В корневой папке проекта создан файл results.csv.

Содержимое файла results.csv:

```csv
Student ID,Student Name,Criterion,Score,Final Score
001,Ivan,Homework,8.00,9.00
001,Ivan,Exam,10.00,9.00
```
